# Notepad++ 功能差异

对照依据：[Notepad++ 官方用户手册](https://npp-user-manual.org/docs/user-interface/)、[编辑](https://npp-user-manual.org/docs/editing/)、[搜索](https://npp-user-manual.org/docs/searching/)。检查日期：2026-10-18。这是主要能力对照，不宣称逐条覆盖其全部菜单或插件生态。

| 能力 | 当前情况 |
| --- | --- |
| 多标签、新建/打开/保存、查找替换、转到行 | 已有 |
| 基于扩展名的语法着色、括号匹配、行号、空白显示、缩放 | 已有；新增手动语言菜单及逐文档会话保存，语言定义和主题数量仍少于 Notepad++ |
| 高分屏 | 新增 Windows PerMonitorV2 与框架控件/对话框缩放；多屏实际视觉验收待做 |
| 内置代码字体 | 新增 JetBrains Mono 全部 8 字重及斜体，6–72 pt 字号菜单 |
| 全部保存、全部关闭 | 新增；取消关闭时保留文档，仍逐个确认未保存内容 |
| 行复制/删除/上下移动、大小写、删除行尾空白 | 新增；编辑命令支持撤销 |
| 换行格式转换 | 新增 CRLF、LF、CR |
| 书签 | 新增标记边栏、切换、前后循环导航、全部清除 |
| 代码折叠 | 新增折叠边栏和全部折叠/展开；仅在相应词法器产生折叠层级时有效 |
| 多光标、矩形选择、多处输入 | 启用 Scintilla 支持 |

| 跨标签搜索、结果展示、标记全部 | 新增跨标签搜索、限额递归文件夹搜索、结果标签页、结果导航、匹配高亮；文件过滤、后台取消、独立停靠面板待实现 |

| 自动补全、调用提示、函数列表 | 新增文档单词 + 已配置语言关键词补全、自动触发开关和 Ctrl+Space；调用提示、函数列表、跨文件语义补全待实现 |

## 手工验收建议

- Windows 在 100%、150%、200%、250% 缩放下检查中文菜单、标签栏、状态栏与两个对话框；跨不同 DPI 的显示器拖动主窗口，确认窗口、字号与边栏随之变化。
- 未安装 JetBrains Mono 的机器上，离线启动 EXE，逐一选择字重和斜体，查看 `Il1 0O {} [] =>`，确认字形与字符对齐。
- 开启多个文档，修改内容，检查全部保存、关闭时取消的行为；测试折叠 Python/C++ 等不同语言。
- Ubuntu/macOS 分别检查构建、随程序字体加载、原生缩放与新菜单；当前开发环境只执行了 Windows 构建和自动化测试。

## 第二轮验收

- 自动化测试覆盖 UTF-8 / UTF-8 BOM / UTF-16 LE/BE 含中文和非 BMP 字符的往返、BOM 原样保存、无效编码和有损转换阻止保存。
- 覆盖手动会话载入、损坏文件拒绝载入、未命名文档恢复、取消/放弃关闭、正常重启的光标和偏好恢复、多实例目录锁。
- 覆盖跨文档结果文本与导航、匹配高亮和清除、排序去重撤销、行注释、制表符转换和混合换行保留。
- 当前环境执行了 Windows 构建和真实 Scintilla 控件测试；三个平台的菜单、定时器与用户配置目录接口均已接入，Linux/macOS 仍需对应系统构建和交互验收。

## 第三轮验收

- 使用真实窗口父控件转发 Scintilla 通知，验证键入录制、保存/载入、非法消息拒绝、回放单步撤销、标签切换停止录制。
- 验证文档单词和 C++ 关键词候选、补全文本插入、自动触发关闭后仍可手动补全、开关持久化。
- 验证递归 UTF-8/UTF-16 文件搜索、`.git` 与二进制跳过、未保存文档内容优先、文件打开后继续导航、源编辑及磁盘变化使结果失效、非法正则保留当前工作。
- 新菜单按会话与文件、编码、搜索结果、文本处理、书签与折叠、宏、代码补全分组；Windows 已构建验证，GTK/Cocoa 的目录选择和菜单接口待对应系统实测。

## Unicode 分类与搜索边界专项

参考原版源码快照 `fd2f5c27839e943518b5a53325ffd5e95bb3e0d9`：

- [Boost 搜索适配层](https://github.com/notepad-plus-plus/notepad-plus-plus/blob/fd2f5c27839e943518b5a53325ffd5e95bb3e0d9/boostregex/BoostRegExSearch.cxx)：Windows 原生 traits；以文档开头为 base、目标上界为 end；反向遍历重叠候选，保留结束位置最远的最长匹配。
- [查找与替换行为](https://github.com/notepad-plus-plus/notepad-plus-plus/blob/fd2f5c27839e943518b5a53325ffd5e95bb3e0d9/PowerEditor/src/ScintillaComponent/FindReplaceDlg.cpp)：CRLF 整体推进，以及批处理 EMPTYMATCH_NOTAFTERMATCH 策略。

本项目显式选用 Boost Win32 traits，解决当前 MinGW 默认选择 C++ locale 导致的非 ASCII 分类差异。用 Windows GetStringTypeW 作为独立测试依据验证 `\w`、`\d`、`\s`、POSIX alpha/upper/lower；验证非 ASCII 大小写匹配、否定类与 Emoji、固定宽度后顾、中文 UTF-8 字节定位及文档/范围锚点。UTF-8 转换和位置表一次扫描生成，不依赖已弃用的 codecvt。

共享内核统一反向重叠匹配和零宽推进，批处理跳过紧随非空匹配的空匹配；不在 CRLF 内部停留。右侧范围上界作为输入结尾，左侧仍可供后顾断言读取。此次为源码对照与 Windows 自动化验证，未宣称对安装版本进行完整 UI 差分验证。

仍待对照：复杂扩展模式、补充平面字母类别、后顾中代理对的完整字符行为、GTK/Cocoa 的分类和 locale 差异。未添加 ICU 属性语法或自动 Unicode 归一化。

## 复杂 Unicode 模式专项

修复 UTF-16 适配的具体差异：精确补充平面字符类不再按单个高代理项匹配，补充字符的量词作用于完整字符；否定类、跨代理块/跨平面的范围、引用和命名捕获替换保持 UTF-8 定位。范围会排除独立代理项，避免 BMP 范围泄漏到补充平面。新增 `\x{10000}`–`\x{10FFFF}` 的码点适配，越界码点在编辑前拒绝。此码点适配及整字符语义属于本项目行为，不据此宣称与原版所有 UTF-16 边缘行为一致。

模式转换按扩展模式作用域识别注释和字面量，包括 `(?x)`、`(?-x)`、嵌套局部选项、CR/LF 注释结束和 `\Q...\E`。适配过程不增加捕获编号。测试验证共享高代理项的 Emoji 区分、正负字符类、BMP/补充平面混合范围及范围上界、十六进制和字面量量词、固定宽度 Emoji 后顾、命名捕获替换及整次撤销、无归一化，以及非法码点/不同 UTF-16 宽度后顾不修改缓冲区。

本轮验证为 Windows 自动化测试。补充平面字母属性、完整大小写折叠、字素簇、复杂排序元素、任意长度后顾和其他平台差异仍待处理；Boost 支持的属性名不等同于 ICU/PCRE 属性全集。

## 完整 Unicode 支持（ICU 可选模式）

新增显式 ICU 模式，内置 ICU4C 78.1 / Unicode 17.0。Boost 保留默认行为；ICU 提供通用类别、脚本/脚本扩展、区块、二元属性、UnicodeSet 交集、字面串完整大小写折叠和 `\X` 扩展字素簇。此模式扩展 Unicode 能力，采用 ICU 语法，不能宣称与原版 Boost 语法完全兼容。拒绝未知转义，避免把 `\K` 等构造误当字面量。

使用 ICU UText 的原生 UTF-8 索引，通过捕获位置桥接已有 Boost format_all 替换格式；查找和替换不改写源文档用于匹配，保留原始大小写与字节范围。ICU 整词使用完整 Unicode 字母、标记、数字、连接符和 Join_Control 分类。正反向、范围和批处理零宽策略沿用共享内核。

Windows 静态编译 ICU 和内嵌完整数据；其他平台分发 unicode/ 数据目录。匹配限制为 2000 ms / 8 MiB 栈。Windows 自动化验证：中文和补充字母、脚本扩展、Emoji/White_Space/Mark 属性与集合交集，ß/SS、ﬃ/FFI、sigma、Deseret 折叠，组合音符/家庭/肤色/旗帜/键帽/CRLF/Jamo/印度连写字素簇，原文捕获替换、撤销、反向字节位置、选区、Unicode 整词、非法属性与 Boost 模式保留。GTK/Cocoa UI 已接入但未在当地系统实测。

限制：ICU 字符类使用单码点大小写闭包，字符串字面量才执行 1:n 完整折叠；不做自动 Unicode 归一化，不支持 ICU 以外的属性语法及任意长度后顾。Win7 尚需实机验证。
