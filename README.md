# NotepadSharp

NotepadSharp 基于 [Scintilla](https://www.scintilla.org/) 打造。编辑组件是 Scintilla 5.5.8，语法着色来自 [Lexilla](https://www.scintilla.org/Lexilla.html) 5.5.4。本项目采用与 Scintilla 相同的开源许可，见 `LICENSE.txt`。Scintilla 与 Lexilla 的版权归 Neil Hodgson 及其贡献者，源码位于 `third_party/`。

Windows、Ubuntu 和 macOS 使用同一套编辑命令：

- 新建、打开、保存、另存为、关闭、退出
- 撤销、重做、剪切、复制、粘贴、删除、全选
- 查找、查找下一个、查找上一个、替换、全部替换、转到行
- 自动换行、行号、空白字符、换行符、缩放
- 按扩展名选择词法并做语法着色
- 命令行传入一个文件路径时直接打开

Windows 目标子系统是 6.01，以 Windows 7 SP1 为兼容目标；新增 ICU 依赖后仍需 Win7 实机验证。Scintilla 的高 DPI 接口按运行时检测加载，Windows 7 上会退回 GDI。

## 构建

Boost.Regex 和 ICU4C 78.1（Unicode 17.0）源码与数据均随仓库提供，CMake 静态构建，无需另装依赖或联网下载。Windows 内嵌 Unicode 数据，Ubuntu/macOS 的 `unicode/` 数据目录须与程序一同分发。

需要 C++17 编译器和 CMake 3.16 或更高版本。

Windows（Visual Studio 2019/2022，或 MinGW-w64）：

```bat
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release
```

用 MinGW 构建时，C++ 标准库会静态链进程序，避免系统里另一份旧的 `libstdc++-6.dll` 导致启动失败（提示找不到 `filesystem` 一类的程序输入点）。Windows 7 上如果使用 MSVC 构建，还需要已安装 Universal C Runtime（KB2999226）。MSVC 构建使用静态 VC 运行库。

Ubuntu：

```bash
sudo apt install build-essential cmake pkg-config libgtk-3-dev libfontconfig1-dev libwxgtk3.2-dev
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

macOS：

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

生成的程序名是 `notepadSharp`。

第三方源码和许可证在 `third_party/scintilla` 与 `third_party/lexilla`。

## 高分屏和代码字体

Windows 使用 PerMonitorV2（旧系统退回 PerMonitor / System DPI），支持 `WM_DPICHANGED` 建议窗口位置和大小，标签栏、状态栏、查找/替换及转到行对话框按 DPI 缩放。Windows 保留 GDI ClearType 渲染，以便正确使用进程内存中的私有字体；无需安装字体，兼容 Windows 7。GTK 和 Cocoa 使用各自原生缩放机制。

内置 [JetBrains Mono 2.304](https://github.com/JetBrains/JetBrainsMono/releases/tag/v2.304)，包含 Thin、ExtraLight、Light、Regular、Medium、SemiBold、Bold、ExtraBold 八种字重及对应斜体，共 16 个 TTF。字体采用 SIL OFL 1.1，许可证位于 `assets/fonts/OFL.txt`。矢量字体不需要为每个字号准备位图，字体菜单可选择 6–72 pt，并可继续使用编辑器缩放。默认 12 pt / Regular；语法关键字至少使用 Bold。字体主要覆盖代码所需的拉丁字符，中文由系统字体回退。

Windows 字体直接嵌入 EXE。Ubuntu/macOS 通过进程内字体注册使用程序旁的 `fonts/` 目录，分发时请一同保留。Ubuntu 构建依赖中需额外安装 `libfontconfig1-dev`。字体选择和视图设置在所有标签页之间共享，并随会话持久化。

## 新增编辑能力

“代码工具”菜单提供：全部保存/关闭、复制当前行或选区、删除行、移动选中行、Unicode 大小写转换、删除行尾空白、CRLF/LF/CR 换行格式转换、书签导航、全部折叠/展开。左侧两个符号边栏分别用于书签和代码折叠。支持 Ctrl+鼠标添加多个选区与矩形选择（平台修饰键遵循 Scintilla 默认设置）。

查找/替换支持正则表达式，使用内置 Boost.Regex 1.90.0，支持 `\1`、`$1` 及命名捕获替换；正逐步对齐 Notepad++ 的选项与边界行为。零宽匹配会向前推进，全部替换可完整删除所有匹配内容，并可一次撤销。

Windows 新快捷键：Ctrl+Shift+S 全部保存，Ctrl+Shift+W 全部关闭，Ctrl+D 复制行/选区，Ctrl+F2 切换书签，F2 / Shift+F2 导航书签。原有菜单和快捷键共用命令处理。

## 会话、恢复与跨文档搜索

- 自动保存已打开文件列表、光标、字号/字重/斜体、缩放、换行与空白显示等设置，正常退出后下次启动恢复；已明确放弃的未保存修改不会重新出现。
- 每 30 秒写入一次恢复快照，包括未命名和已修改文档；异常退出后优先恢复最近一次成功快照。快照最多 64 MiB / 1000 个文档，不保存撤销历史。正常退出仍会询问是否保存修改。写入失败会提示一次，成功恢复写入后重置提示状态。
- “代码工具 → 会话与文件”可手动保存/载入 `.nss` 会话，包含未保存内容。载入前先验证文件，再确认当前修改；不会自动覆盖原文件。
- Windows 状态目录为 `%APPDATA%/NotepadSharp`，Linux 为用户配置目录下的 `NotepadSharp`，macOS 为 `~/Library/Application Support/NotepadSharp`。会话以普通文件保存。多个实例中只有取得目录锁的实例执行自动恢复和自动快照，避免相互覆盖；其他实例仍可手动保存会话。
- “代码工具 → 搜索结果”支持在全部打开的文档中查找、只读搜索结果标签页、当前文档匹配高亮和清除标记。Windows 的 F4 / Shift+F4 跳转结果；所有平台也可通过菜单导航。结果最多 10000 条，源文档编辑或关闭后需重新搜索。零宽匹配可搜索，不产生可见范围高亮。

## 编码与更多文本操作

支持 UTF-8、UTF-8 BOM、带 BOM 的 UTF-16 LE/BE 读取与原编码保存，可在“代码工具 → 编码”中选择输出编码。没有 BOM 且不符合 UTF-8 的内容按 Latin-1 读取；GBK/GB18030 和无 BOM UTF-16 的自动识别尚未实现。Latin-1 无法表示的字符会阻止保存，原文件保持不变。编码选择不属于文本撤销历史。

新增按行升序/降序排序、删除重复行（保留首次）、切换行注释、制表符按 tab stop 转空格。排序、去重、制表符转换在无选区时作用于全文，有选区时作用于选中的完整行。注释命令无选区时只处理当前行，适用于已定义行注释符号的词法器。排序为区分大小写的字节顺序，排序和去重使用当前文档换行格式；注释和制表符转换保留各行原有换行符。

## 文件夹搜索

“代码工具 → 搜索结果 → 在文件夹中查找”先选择目录，再设置查找文字、区分大小写、全字或正则选项。递归读取普通文件，跳过 `.git`、符号链接、包含 NUL 的非 UTF-16 文件，以及超过 8 MiB 的文件。最多检查 2000 个文件、读取 64 MiB、输出 10000 条结果；达到上限会在结果中注明。当前采用同步限额搜索，尚不支持文件名过滤、后台进度/取消和目录批量替换。

已打开的文件优先搜索编辑器中的内容，包括未保存修改。跳转结果时检查源内容；未打开文件的内容在搜索后变化，会要求重新搜索。Windows/Linux 可用 F4 / Shift+F4，所有平台均可从菜单跳转。

## 宏

“代码工具 → 宏”提供录制开关、停止、回放，以及 `.nsm` 文件保存/载入。Windows Ctrl+Shift+R 切换录制，Ctrl+Shift+P 回放。录制以当前标签页为范围，切换或新建标签页自动停止；状态栏显示“宏录制中”。回放作用于当前可编辑文档，并可一次撤销。

当前记录 Scintilla 的输入、光标/选区移动及基本编辑命令，录制时复制文本参数，避免使用临时指针。宏文件载入会验证消息白名单和文本长度。最多 10000 步 / 4 MiB 文本。文件操作、查找替换对话框、排序等应用级命令尚不能完整录制；剪贴板命令回放时使用当前系统剪贴板。现支持重复次数及“运行至文件末尾”；命名宏列表仍待实现。

## 单词补全

Ctrl+Space 或“代码工具 → 代码补全 → 单词补全”显示候选，可用方向键和 Enter/Tab 选择，Esc 关闭。默认输入两个 ASCII 标识符字符后自动触发，菜单可关闭自动触发；开关随会话持久化。录制宏时不弹出自动补全。

候选来自当前光标附近最多 1 MiB 的文档单词和当前词法器已配置的关键词，按字母顺序去重，最多 200 项；支持 ASCII 标识符，尚不提供类型推断、跨文件符号解析和函数调用提示。

## 按已安装 Notepad++ 实机菜单继续对齐

已查看 `D:/ProgramFiles/Notepad++` 的宏对话框、空白字符子菜单、标签页右键菜单，以及文件/编辑/搜索/视图菜单。

- 宏菜单新增“重复运行宏”和“运行宏到文件尾”。多次运行作为一次撤销；到文件尾模式在光标不能前进且文本没有缩短时停止。运行受到 10000 次、100000 条编辑指令、5 秒及 16 MiB 文本增长限制，触及限制会提示。
- 空白处理新增换行符转空格、移除行首尾空白并连接各行、全部空格转 TAB、仅行首空格转 TAB。CRLF 作为一个换行处理；空格转 TAB 按当前 tab stop 计算，不把单个空格替换成 TAB，并保留原有换行符。
- Windows 标签页右键菜单提供保存、另存为、副本、重新读取、只读、关闭其他/左侧/右侧，以及复制完整路径、文件名、目录路径。Ctrl+Tab / Ctrl+Shift+Tab 循环切换标签。
- 先前按实机菜单加入的重新读取、副本另存为、批量关闭、只读、文档统计、空行清理、相邻去重、逆序、忽略大小写/行长排序、多重选取与匹配括号命令均保留。
- Windows 工具栏采用上图标下文字，图标用矢量几何按 DPI 绘制；已启用 Common Controls v6 以正确显示透明图标。

Windows 构建、真实 Scintilla 行为测试和标签右键菜单界面检查已完成；Linux/macOS 的新增共享命令及数字输入接口仍需对应系统构建验收。并非已达到 Notepad++ 全部功能对等。

## 手动语言与视图操作

语言菜单提供自动识别、普通文本、C/C++、Python、JavaScript/TypeScript、Rust、JSON、XML、HTML、CSS、Markdown、Shell、Lua、SQL、YAML、CMake、Makefile、Ruby、Perl、PHP。可用于未命名文档和特殊后缀文件。手动选择只影响编辑器解析，不修改文件内容或后缀；选择“自动”恢复按扩展名判断。切换语言会重新着色并重置折叠层级，保存/另存为后保留手动选择。

会话格式升级为 `NotepadSharpSession3`，保存每个文档的语言选择和编辑器只读状态，仍可读取此前的 Session2 文件。

“代码工具 → 视图”新增全屏、总在最前、折叠/展开当前层次、隐藏选中行、显示所有隐藏行。Windows F11 切换全屏，退出时恢复原窗口大小位置；Ctrl+Alt+F 折叠当前层次，Ctrl+Alt+Shift+F 展开当前层次。隐藏行保留第一行可见；这些显示操作不修改文件内容。全屏/置顶及临时隐藏行不随会话恢复。

Windows 已实机检查全屏进入和窗口恢复；自动化测试覆盖语言着色、普通文本颜色清理、当前折叠、隐藏行、语言和只读状态恢复以及 Session2 兼容。

## 文件变更检测、监视与文件历史

- 每 2 秒比较打开文件的修改时间和大小。发现外部变化时询问是否重载，默认保留编辑器内容；拒绝后不会对同一磁盘版本反复询问。再次保存到该路径前会确认是否覆盖外部版本。
- “代码工具 → 会话与文件 → 监视文件”用于已保存、无修改的文档，以只读方式随磁盘更新重载并跟随末尾。停止监视恢复原只读设置；监视状态本身不随会话恢复。当前为整文件轮询重载，会清空旧撤销历史，不是增量日志读取。
- 文件删除或无法访问时保留缓冲区、停止监视并提示，之后重新写入也需确认。删除后重新出现的文件需手动重新读取或保存后重新启用监视。
- 文件菜单新增最近 20 个文件，窗口菜单列出当前文档，可直接切换。最近记录随会话保存。“重新打开最近关闭的文件”恢复本次运行中最近关闭的磁盘文件；Windows 快捷键为 Ctrl+Shift+T。尚不恢复关闭时明确丢弃的未保存内容。
- 恢复完整快照后，文件可能已在外部变化，因此保存恢复内容前会保守地确认覆盖；确认后正常保存并重置检测基线。

Windows 已通过外部变化、取消/确认覆盖、监视末尾、文件删除和恢复、最近记录与关闭重开测试，窗口菜单已实机检查。GTK/Cocoa 已接入对应原生提示、定时器及动态菜单，仍需相应系统实测。修改时间和大小相同的原地修改不保证被识别；大文件高频监视尚未专项优化。

## 查找功能对齐

Windows Ctrl+F / Ctrl+H 现打开可保持显示的查找窗口，包含查找、替换、标记三个页。执行后不关闭窗口，也不阻止切回编辑器；状态和错误在窗口内显示。查找/替换框保留本次运行最多 20 条历史。单行选区会作为打开时的查找目标。

- 支持上一处/下一处、大小写、全词、反向、循环和选区范围。关闭循环后，到范围边界即停止；循环搜索能匹配跨越原光标位置的内容。
- 普通模式按原文字搜索；扩展模式支持 `\n`、`\r`、`\t`、`\0`、`\xHH` 和 `\\`，无效转义会给出提示。
- 正则统一使用内置 Boost.Regex 1.90.0（BSL-1.0），无需额外 DLL 或在线依赖；支持跨行开关、行内模式、后顾断言、命名捕获、`\K` 和 `\R`。UTF-8 字节位置与宽字符匹配结果统一转换；Windows 显式使用原生 Win32 分类与大小写表，修复 MinGW 默认 C++ locale 的差异；通配点、字符类和否定类适配代理对。反向正则考虑重叠结果，按最远结束位置及最长匹配选择。
- 计数不移动光标；可列出当前/所有打开文档的结果，或标记当前文档的匹配。结果页和高亮仍使用现有搜索结果机制。
- 单次替换仅替换当前已选中的准确匹配，否则先定位下一处。全部替换支持选区范围，并跟踪替换造成的长度变化；无循环且未启用选区时，从光标沿搜索方向确定范围。
- “全部替换打开的文档”处理所有可编辑文档，跳过只读及结果文档，汇总数量，且不会自动写入磁盘。每个文档单独构成一次撤销，不能跨文档一次撤销。不支持与选区范围同时启用。
- 手工编辑会使先前捕获的选区搜索范围失效，需重新选择范围。零宽匹配会按字符前进，防止计数或替换停在同一位置。

本轮 Windows 已实机检查界面、计数及窗口保持打开，自动化测试覆盖范围、方向、模式、换行、捕获、Unicode、NUL、只读、批量替换和撤销。GTK/macOS 继续使用此前的基础模态查找界面，新增共享搜索内核已接入，但完整新界面尚未移植；文件/项目搜索标签、透明度和搜索历史跨重启保存仍未实现。

### Boost 模式的 Unicode 与搜索边界

Windows 正则的 `\w`、`\d`、`\s`、POSIX alpha/upper/lower 分类及非 ASCII 大小写匹配，使用与 Notepad++ 相同的 Boost Win32 traits。分类遵循系统的 Windows 表和 locale，未引入 ICU/PCRE 的 Unicode 属性规则，也不进行 NFC/NFD 归一化。UTF-8/宽字符转换及字节位置映射改为单次线性扫描。

范围语义对照原版 Boost 搜索适配层：左侧保留文档前缀，`\A` 指文档开头，后顾和词边界可读取范围前的字符；右侧以目标上界结束输入，`$`、`\z` 和前顾受该上界限制。反向搜索包含重叠候选，优先结束位置最远、同一结束位置下最长的匹配。

零宽搜索按完整字符推进，CRLF 作为一个换行跳过，不停留在 CR/LF 中间。计数、全部替换、结果列表、标记和文件夹搜索，不接受紧跟前一非空匹配的空匹配，与原版批处理策略一致。例如 `a*` 搜索 `ab`，批处理为两处，替换为 `X` 后得到 `XbX`。

Windows 测试以 `GetStringTypeW` 独立核对分类，并覆盖中文、重音拉丁字母、希腊文、西里尔文、阿拉伯/全角数字、Unicode 空格、组合标记、Emoji、反向重叠、范围锚点、前后顾和零宽推进。固定宽度后顾仍遵循 Boost 的 UTF-16 单元限制；复杂扩展模式、补充平面字母分类及 GTK/Cocoa 平台差异仍待继续对照，不宣称完全兼容。

### Boost 模式的复杂 Unicode 正则

Windows 的 UTF-16 适配已独立到 `src/UnicodeRegex.cpp`，不会额外引入捕获组。支持补充平面字面量及其量词、精确/否定字符类、混合 BMP/补充平面字符类、跨平面范围、`\x{1F600}` 十六进制码点，以及这些模式的命名捕获和替换。例如 `[😀]` 不会误匹配 `😁`，`😀+` 会按完整 Emoji 重复，`[\x{1F600}-\x{1F64F}]` 按码点范围匹配。范围分解使用有限个代理对区间，不逐字符展开。

适配器识别 `(?x)`、`(?-x)`、局部 `(?x:...)` 及嵌套恢复；注释内的括号、方括号不会参与转换。`#` 注释遵循 Boost 的换行分隔符，`\Q...\E` 中的空白、井号和元字符保留字面含义。引用结束后的量词仍作用于完整补充平面字面量。

补充平面字面量/同宽字符类可用于固定宽度后顾；混合一个与两个 UTF-16 单元的后顾仍由 Boost 拒绝，并在编辑前提示。`\w`、大小写和属性名继续遵循 Boost Win32 表，尚不支持完整补充平面字母分类、完整大小写折叠、任意长度后顾、ICU/PCRE 属性全集或字素簇语义；组合字符不会自动归一化。十六进制补充码点和整字符量词是本项目的 Unicode 适配行为，未宣称与安装版原版逐例完全一致。

## 完整 Unicode（ICU）模式

在查找窗口选择“正则表达式”，再勾选“完整 Unicode（ICU：属性、折叠、字素簇）”。默认仍使用 Boost，已有表达式可继续沿用；两个模式分别采用各自语法，不自动互相回退。GTK/Cocoa 基础查找窗口也提供对应选项，尚需相应系统构建及实测。

- Unicode 17.0 属性：`\p{L}`、`\p{Script=Han}`、`\p{scx=Hira}`、`\p{Block=Basic_Latin}`、`\p{Extended_Pictographic}` 等；支持 ICU 的属性别名、否定属性及 UnicodeSet 交集。
- 关闭“匹配大小写”后，字面串按 Unicode 完整折叠匹配，例如 `strasse` 匹配 `Straße`，`ffi` 匹配 `ﬃ`，并处理希腊 sigma 和补充平面字母。`(?i)` / `(?-i)` 可局部控制。字符集合按 ICU 的单码点闭包规则工作，`[ß]` 不等同于字符串 `ss`。
- `\X` 匹配扩展字素簇，包括组合音符、Emoji ZWJ 家庭、肤色、旗帜、键帽、Hangul Jamo、印度文字连写和 CRLF；`\X{2}` 匹配两个字素簇。
- 计数、标记、结果列表、正反向查找、选区、跨文档/文件夹搜索共用新内核；ICU 全词过滤使用 Unicode 类别。匹配位置和捕获保留原始 UTF-8 字节，不先修改或折叠文档文本。替换保留 `\1`、`$1`、`$+{name}` 等既有 Boost format_all 引用方式。

ICU 使用内嵌数据，Windows 无额外运行库 DLL；exe 因数据增加约 33 MB。Ubuntu/macOS 需分发旁置的 `unicode/icudt78l.dat`。执行设置 2000 ms 时间限制和 8 MiB 回溯栈限制；超限或非法表达式会反馈错误。ICU 不支持的 Boost 构造（如 `\K`）会提示错误，应切回 Boost；Unicode 属性集合以 ICU 支持范围为准，未添加规范化/口音忽略或任意长度后顾。两种模式与 Notepad++ 的语法/边界差异仍应按实际表达式核对。

本轮 Windows 编译、自动化测试及查找界面/ICU 属性计数实机验证通过；Win7 仍需实际系统测试，未引入非系统 DLL，不能仅凭子系统版本保证新依赖在所有旧系统上的行为。
